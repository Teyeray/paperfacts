## 目标与已确认输入

保留 MinerU / PaddleOCR-VL 的双路全文抽取，用一个自动选择候选、读取原始页面、输出完整事实的辅助步骤。纠错与找回两路共同遗漏同等重要；日常运行无需人工选择区域或逐条确认，无法确定的项目自动留为未决。

- 用户确认首轮沿用现有 TCO 领域与样例、现有数据目录、项目现有模型服务。
- 用户确认暂不考虑金额预算：金额上限与价格核算不作为方案前置关口；仍保留请求/重试上限和实际用量记录。
- 配置文件的 `data_root` 为 `data`，实际入口可能存在环境覆盖；当前 checkout 未发现 PDF。T0 必须核对有效路径、PDF SHA 和既有 A/B 产物，不能把存在 gold 等同于存在可运行输入。
- 用户本次授权更新设计与 HTML 行动方案，不授权产品实现、真实模型调用、发布或推送。
- C 是同一论文的额外读取方式，不是独立科学来源；不采用三票多数决。
- 保留 T0–T5 与既有架构范围：原生文字及可定位坐标、最多一次必要局部放大、T5 有限自动采纳均留在本计划内；本轮不另加架构限制或拆出后续项目。

## 最小架构

PDF → A/B → compare；同时从原 PDF 文字层独立找相关页。候选选择合并两种来源：A/B 风险位置与独立发现的相关页。C 用原图独立抽取原始事实，结果在旁路报告中与 A/B 对照。真实验收通过后，把同一补证函数接到 `workflow.run_document` 的 compare 后、export 前。

- 第一版独立候选默认整页，同时保留原生文字及可定位的文字坐标。精确、完整的 A/B 引用可复用已有区域裁图；所有 PDFium 调用、页码与坐标转换遵循 pdf.py 现有规则。
- 每篇最多 4 个候选，风险与独立发现各有 2 个配额。先按区域去重；同页整页覆盖内部小框时合并触发原因并保留原框供必要放大，几何覆盖不代表缩图后仍可读。交替从风险、独立列表取尚未选中的候选，直到各占 2 个名额；一池不足时从另一池补足。其他上限按风险 floor(limit/2)、独立剩余名额分配，实验内固定。同一候选可保留两种来源标签，但只占选中池的一个名额、初读只花一次逻辑请求，不因双标签重复请求；仍允许一次必要放大。
- 风险池按 P1 数值/单位/条件冲突或无出处、P2 单路缺失、P4 一致但有复杂表头等风险排序；独立池为 P3 相关页和扫描页，同级按页号与坐标确定顺序。无法定位到页的项记录未决，不虚构可读区域。
- 独立发现不得以 A/B 已找到的样品或 SourceBlock 为前提。A/B 引用过某页不代表该页全部事实已覆盖，不能据此移出独立池。文字层不可用的页作为扫描页候选；未处理、超限或无法判断覆盖的页必须记录，不能声明全文核验完成。
- C 提示继承 profile 的 sample_definition、field_scope、paper scope 与 article type 约束，避免把综述引用对象、范围外事实当成本论文样品。针对已有事实可给样品标识；独立发现不限制为既有样品列表。不给 A/B 数值、单位答案、比较结论或解析文本。
- 输出 scope、entity、样品原名、field、value_raw、unit_raw、condition、condition_status（stated / not_stated / unclear）与可见行列/图例依据。页码、裁图框、实际 PDF/图片 SHA 由程序绑定，不能由模型虚构。单位转换复用 profile 的 UnitRegistry。
- 样品匹配复用现有 entity + sample_key，只有唯一匹配才关联已有样品；未匹配或多重匹配保留旁路，不按同名、顺序或数值猜测归属。paper scope 事实按其作用域处理，不伪造样品行。
- 结果最少包含 outcome、reason、原始观察和出处。数字出现匹配只作诊断；不能使用现有 `validate.adjudicate` 直接确认事实。
- 跨页缺上下文、样品歧义、曲线估读、结构损坏均不自动采纳。近似曲线读数沿用既有 figures 的独立语义。

## 实施范围与资源边界

先复用 pdf.py、CropStore、VisionClient、storage 和现有规范化。工具实现按两项职责平铺：visual_candidates.py 负责确定性候选选择，visual_evidence.py 负责独立读图与旁路报告，避免把候选与读图堆进一个长文件；实验与评分入口放在 eval/。不新增框架或子包，不引入 pypdf/PyMuPDF/分割模型，不扩充 Backend，不新增队列、数据库、独立 Web job 或专门的三路界面。

按用户后续要求，工程开发与具体论文分析分开：先使用合成 PDF、假客户端和人工构造的评分案例验证工具；真实 T0 输入、使用史、论文划分与 G1/G2 证据仍待准备。工具可运行不表示科学验收通过，不能据此跳过 T4/T5 的原有关口。实际进展和验证结果见[实施记录](../plans/2026-10-05-auto-visual-evidence-progress.md)。

首轮实验建议每篇最多 4 个去重候选、每候选最多 2 次逻辑读图（正常读取＋一次必要放大）；客户端每次请求最多重试 1 次（retry_attempts=2 表示总尝试 2 次），每策略最坏每篇 16 次 HTTP 请求、11 篇 176 次，两种 C 策略独立执行最坏 352 次；不能假设缓存交集一定存在。这是运行边界，不是金额预算；按用户回复不设金额审批关口。候选/请求数、token、耗时与超限项进入报告，扩充候选覆盖时重新固定实验参数。C 串行运行并遵守现有全局模型并发控制。无需新预算服务。

复用请求级缓存；修复 crop 文件身份缺少 max_pixels 的问题。manifest 分别记录 document_id / 文档身份 SHA 与实际读取 PDF 的字节 SHA，并保留已有 parts 的各部分 SHA、first_page / pages 区间：含 SI 的合并文档身份不必等于 source.pdf 文件 SHA。沿用已有文档目录，不用文件 SHA 另建文档身份或回填改写旧 parts。报告另记实际图片 SHA、冻结 A/B 与最终 dataset 摘要、profile、模型/提示词/参数、代码与 gold 版本。旧实验不自动删除；纯读取/导出零模型调用。

## 验收与接入

T0 先列出 11 篇论文在既有抽取、调参、gold 修订与 C 规则设计中的使用史。6 篇开发 / 5 篇留出只作暂定可复现划分，冻结前结合使用史与冲突、同错、共同漏检、正确对照、复杂单位/条件和不可判定案例覆盖确定。只有未参与 C 候选规则、prompt 或采纳规则设计的论文，才可称为 C 留出；不称为系统从未见过的论文。缺少合格留出或真实案例时明确记为证据不足。

先冻结输入，再独立运行 C，不调用完整 run_document 隐式重跑 A/B。G1 对照冻结 A/B 的完整事实集合，G2 对照冻结最终 dataset 作离线采纳回放。在开发集同时冻结候选规则、prompt 和拟采纳字段/证据类型及规则，再一次性使用 C 留出集验收；根据留出错误改规则后，原留出降为开发证据，需新的、未参与 C 规则设计的论文再验收。

评分前先对原图核验所评页范围内的相关事实和排除项，不能直接把既有稀疏 gold 当成穷尽真值。未标注观察先列待核验，不直接算 extra；标注未完整时只能报告“已标注事实召回”，不能称完整页或全文召回。按文档 + scope / entity / 对象 + 字段 + 条件及条件状态 / 测量状态匹配事实，逐事实一对一去重；重复读取、重复观察或两路已有的相同事实不增加收益。值、单位与归属均按完整事实核验，不能只按数字命中评分。

G1 分别计算纠错净收益与共同补漏净收益，分别扣除各自引入的错误建议。两个目标等重：二者都为正才全量通过，一边收益不能抵消另一边退化；缺少任一目标的有效机会是证据不足。G2 逐字段、逐证据类型报告实际触发机会、采纳数与独立论文数；零触发不能过关。批准范围须无错误采纳、无正确值回退且净收益为正；小样本零错误只支持当前范围试用。评估标注属于开发验收，不是日常逐篇人工操作。

工程验收要求：确定性候选、原图可追溯、严格解析、失败隔离、缓存正确、离线零网络、预算有界。真实验收分别报告候选召回、完整元组正确率、纠错/误改、找回遗漏、弃权率、请求数和耗时；不改变 eval/score.py 的 figure_only 旧语义。

先验收旁路净增益，再在 T4 接入自动补证；T5 仍是本计划内单独验收的有限采纳任务。采纳按最终决策的原因白名单处理：明确遗漏 missing、获准的数字/单位 conflict 可考虑；unanswered、ambiguous、multiple_conditions、multiple_values、non_scalar、unreviewed 等不得借“空白”绕过原拒绝原因。仅允许经验证的字段与证据类型、明确印刷数值、唯一匹配已有样品、单位和条件满足字段要求且规范化/范围校验通过的事实。

原图中的界限、范围、近似与符号必须保留，不得改成精确标量。condition_status 为 not_stated 仅在字段本身无需条件且不存在多状态歧义时可采纳，unclear 不采纳。两路原本一致的值第一版不覆盖，独立发现的新样品不自动建行，曲线估读不填主表。无足够 C 留出证据就保持自动旁路，无人值守照常完成。

生产接入默认关闭新的自动补证设置，不能因旧配置 vlm.enabled / fill_blanks 为 true 而突然调用或填表。启用后普通运行自动执行；关闭后恢复现有双路行为。采用单一 workflow 入口，保留 A/B 数据及二路 compare 含义；将获准采纳记录作为带来源的显式最终决策，相关派生结果与缓存指纹同步更新。

T4 同时处理旧完成论文缺少 C 或 C 已过期的情况，按匹配指纹补跑 C，复用有效 A/B 缓存。C 状态持久记录为完成、部分完成或错误等可辨状态；同指纹的失败/部分结果不在每次批量执行时自动反复请求，只有显式重试或相关输入变更才再试。关闭 C 时新增调用为零；查看、导出不发任何模型请求。

T5 使正常运行与 batch.export_document 共用同一纯采纳决策：读取指纹匹配的 C 证据后决定采用或拒绝；证据缺失或失效时不采纳并说明原因，不由导出触发模型。同步最终 dataset、派生产物与采纳规则指纹，验证运行后导出与独立重新导出一致，避免运行时采纳在导出时丢失或陈旧结果复活。

## 文档与产物生命周期

此设计与 HTML 属版本化文档。源 PDF 保留原位置，只读使用。实验定义、评分和小型可分发合成测试属于 eval/ 或 tests/；私有裁图、响应、冻结输入摘要与运行报告写入 storage 定义的忽略目录 output/ 下的日期与 run-id 子目录。T0 先在 eval/README.md 与 storage 文档规定实际子目录规则，再生成任何运行产物。生产报告路径在 T4 接入时统一由 storage.py 定义。未经允许不删除历史文件。

### 无数据/API 的采纳工具增量

新增 `visual_adoption.py` 纯函数和 `eval/visual_adoption.py` 独立入口；只回放明确声明的数值样品字段，固定支持 missing/conflict，输出逐单元格前后值、依据索引与拒绝原因，不更新主表/Excel。人工完整事实标签仅参与评分，不影响采纳。按字段、原因和印刷证据范围报告机会、采纳、错误与独立文档数；纠错与共同补漏分别计分，零采纳不能通过。无真实留出证据时不开放生产采纳。具体输入契约见 [eval/README.md](../../../eval/README.md#offline-adoption-replay-g2-tooling)。

### 实验生命周期与独立副本

实验入口新增 status、显式 retry 和 export；每次尝试记录 manifest/report 摘要，部分/失败/中断不自动循环重试，旧结果保留。独立副本每次从原始 A/B 重建，同步质量来源、条件、字段计数与完整代表样品行，保存后重读再复用现有 Excel 导出。缺失/过期 C 不留下旧采纳；输入或代码变化须新建冻结运行。`eval/visual_demo.py` 用自动生成的合成 PDF 和固定本地响应演示此闭环，不需要真实文献/API。生产接入及科学验收门槛保持。
